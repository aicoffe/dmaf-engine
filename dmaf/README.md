# dmaf/ — the dmaf-sdlc workflow package (definition layer)

This directory is the definition layer of workflow package **dmaf-sdlc** for [dmaf](https://github.com/aicoffe/dmaf-engine) (the deterministic multi-agent workflow engine): the AI-native SDLC standard process sample. It drives a requirement statement through end-to-end delivery: concept → requirements → design → development — the engine routes deterministically, the LLM conductor dispatches role subagents, humans decide at approval gates, and every step lands in a hash-chained audit ledger.

## Layout

| Path | Contents |
|---|---|
| `manifest.yaml` | Package manifest: name/version/description and compatibility declarations (engine `>=0.6,<0.7`; harnesses: opencode/claude/zcode/cursor/gemini/codex/dsh; `dmaf doctor` reads it for compatibility; shared by add/push/publish) |
| `intro.yaml` | The three market-intro fields what_it_is / what_it_does / how_to_use (`dmaf publish --intro`) |
| `workflows/stages/<phase>/<slug>.md` | 12 stage definitions (frontmatter declaration + execution brief), grouped into 4 phases |
| `workflows/scopes/<name>.md` | scopes: `include_stages` membership + workflow-level metadata (vars, `completion_template`) |
| `agents/` | 8 agents (frontmatter: name/mode/description): `dmaf-conductor` (mode: primary, the orchestrator) + seven SDLC roles — product/architecture/frontend/backend/QA/tech-lead/UX (mode: subagent) |
| `skills/` | Skill library `<category>/<name>/SKILL.md` (flattened by name at install time; names globally unique); index and conventions in [skills/AGENTS.md](skills/AGENTS.md) |
| `hooks.yaml` | Project-level hook configuration (init / on-event; fully commented by default = not enabled) |
| `docs/流程定义指南.md` | Flow definition guide (dmaf v0.6.x, written by `dmaf new`): stage/scope fields, template variables, approval gates, compile error reference |
| `compiled/` | `dmaf compile` artifacts (generated at compile time and committed; byte-deterministic, never hand-edited; the conductor reads `compiled/scope-grid.json` to identify scopes) |

## Two ready-made workflows (scopes)

- **sdlc-standard**, the standard process: all 12 stages with nine human approval gates (intent-accept → spec-review → ue-review → architecture-review → hld-review → lld-review → design-accept → plan-review → pr-review). Approve to proceed, reject to enter a revision loop; the high-fidelity UE and hld stages are on-demand (prototype only when there is a UI, trim the design chain for brownfield per the architecture-impact verdict).
- **sdlc-bugfix**, the light defect-repair process: 7 stages (the whole design chain skipped) — the defect report becomes the intent → a minimal-fix-surface spec (the reproduction test turns green first) → plan → TDD fix → regression system test → PR; it shares the same stage library with the standard process and changes no stage definition.

Stages at a glance — concept `intent-capture`｜requirements `spec-generation`｜design `hifi-ue`*, `architecture-analysis`, `hld-design`*, `detailed-design`, `conflict-resolution`｜development `plan-generation`, `task-breakdown`, `atomic-execution`, `system-testing`, `pr-preparation` (\* on-demand).

## Skill library (skills/)

- **10 capability-domain categories (27 skills)**: requirements(1), architecture(3), backend(3), frontend(4), testing(3), engineering(3), operations(1), security(1), governance(1), stacks(7 — stack bindings: go/java/rust backend, react-mantine/vue3-naiveui frontend, and two UE prototypers).
- **Top-level mechanism skills**: `dmaf/` (the conductor orchestration manual, mounted as the same text in `agents/dmaf-conductor.md`), `rules/` (the public standards library: L0 principles + L1 domain standards ×11 + L2 working guides ×5; index in `rules/SKILL.md`), `create-workflow/` (the workflow-authoring skill).

## Runtime layer and boundaries (not in this directory)

- `.dmaf/` — **engine-exclusive runtime area** (session state and audit, gitignored). Neither agents nor humans read or write it.
- `.opencode/` etc. — harness derivatives (generated by `dmaf install`, gitignored); never hand-edit them.
- **Business deliverables** never go into `dmaf/`: their full paths live in stage `inputs`/`outputs` (supports `{SESSION_ID}` session bucketing); the sample writes to `dmaf-output/` at the project root, and your version control decides whether to keep them.

## Writing workflow definitions

**Read [docs/流程定义指南.md](docs/流程定义指南.md) first**. Prefer letting AI author them: in your harness, trigger `create-workflow` in natural language (Q&A mode for small changes, document mode to convert a written process into dmaf definitions).

## The loop

```bash
dmaf compile && dmaf compile --check   # after definition changes; the artifact diff is the workflow-change review
dmaf install --harness <name>          # deploy agents/skills to the harness after changes
dmaf check --harness <name>            # after deploy / CI: workflow references vs actual harness content
dmaf doctor --harness <name>           # daily self-check: layout / drift / manifest compatibility / reference completeness
dmaf start --scope sdlc-standard --var topic=<prefix> --task "<original requirement>"   # start a session
```

On the harness side the conductor takes over: `/dmaf start "requirement description"` starts; sessions pause at approval gates in `awaiting-approval` and continue on an approval decision (granted to proceed / rejected with revision notes); `/dmaf` answers progress questions in natural language, runs `log`, and re-runs from a chosen stage via fork.

Full command reference: [docs/流程定义指南.md §11 command quick reference](docs/流程定义指南.md) and the dmaf engine manual.

## Upgrading from 0.1.x (the Chinese pack)

0.2.0 flips the entire pack to English sources. Three things to know before upgrading:

1. **先完成在途中文会话再升级 / Finish in-flight Chinese sessions before upgrading.** Definition changes strand in-flight sessions.
2. **哈希门 skipped 文件会残留中文 / Hash-gate `skipped` files stay Chinese.** Assets you modified locally are not auto-updated; review the skipped list, then `dmaf add --force` or handle them manually once confirmed.
3. **产出语言跟随任务语言 / Deliverable language follows your task language.** 中文用户升级后一切照旧：用中文提需求，spec/hld 等交付物与审批门呈现仍为中文（conductor 按你的语言忠实转述）；In English you get English end to end. Existing Chinese artifacts continue in Chinese.
