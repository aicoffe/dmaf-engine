# D-MAF 引擎手册（dmaf / dmaf-engine）

> 语言：中文 | [English](../engine-manual.md)

确定性 multi-agent 路由引擎。核心原则：**Engine 是唯一路由权威，Agent 是受控执行单元**——相同的状态文件 + 工作流定义，永远产生相同的下一跳指令；LLM 只在 Engine 指定的单个动作内发挥判断力。

## 目录与命令面（v0.5.4）

```
dmaf/                       # 定义层（入库）：dmaf 的全部"源"
├── workflows/stages/<phase>/<slug>.md   # stage 库（compile 的输入）
├── workflows/scopes/<name>.md           # scope 成员网格（include_stages）
├── agents/  skills/         # AI 资产（install 安装到 harness）
├── hooks.yaml               # 项目级 hook 配置（可选）
└── compiled/                # 编译产物（引擎管理，入库 + --check 漂移守卫）
.dmaf/<会话>/               # 运行层（gitignore）：引擎独占的会话状态与审计
<业务目录>/                  # 工作流产出物：完整路径写在 stage 的 inputs/outputs（支持 {SESSION_ID} 分桶）
src/  tests/                # 引擎实现（cargo 包 dmaf-engine，二进制 dmaf）
```

命令二进制为 **`dmaf`**（`target/release/dmaf`，或开发期 `cargo run --release --`）。

| `dmaf add (<market条目URL> \| --from <路径\|本地.tar.gz归档\|URL> [--tag vX]) [--dry-run] [--no-install] [--force]` | 把工作流包合入**当前工程**（使用者视角）。源须含 `dmaf/` 布局与包清单。合入语义：目标无 `dmaf/` 先补最小骨架；按 `dmaf/packages.yaml` 账本**哈希门**合并（目标缺失→created、内容相同→unchanged、包属且目标未改→updated、其余→conflicted 且**整体不落盘**）；排除工程自属槽位（`dmaf/manifest.yaml`、`dmaf/README.md`、`dmaf/docs/流程定义指南.md`、`dmaf/packages.yaml`、引擎下发的定义技能 `dmaf/skills/create-workflow/`）与 `dmaf/compiled/`；合入后重编译（命名冲突检测点）；串联 harness 自动探测与部署（`--no-install` 关闭；`--force` 同步作用于串联部署）；账本记录包名/源/tag/逐文件哈希（market 来源另记 digest）。**market 条目 URL**（条目页安装命令形态）走匿名取源 → SHA-256 与 `X-Content-Digest` 二次核对（fail closed）→ 安全解包（拒绝穿越/链接/超限）→ 同一合并核心；`--tag` 钉版本（缺省 latest，账本记 `X-Entry-Version` 实际版本）；本地 `.tar.gz` 归档走同一套安全解包与合入（离线安装） | 2 源/URL 不合法；3 条目 404/信封错误/归档非法；4 合并冲突；5 IO/网络/摘要失配/部署失败 |

### market 对接（auth / publish / add 条目 URL）

对接 market（工作流/agent 集市）的三条命令与共享底座：

| 命令 | 说明 | 退出码 |
|---|---|---|
| `dmaf auth login --token <PAT> [--market <base>]` | 本地格式预检（`dmafmt_` 开头总长 50，不符不发请求）→ `GET /api/me` 校验 → 凭据落用户级配置目录（`%APPDATA%\dmaf\credentials.toml` / Unix `~/.config/dmaf/credentials.toml`，按 base 分键，Unix 0600）。不调用任何 `/api/auth/*` 端点（CLI 不走 OIDC/refresh） | 2 格式/地址；3 校验失败（401 含吊销口径） |
| `dmaf auth logout [--market <base>]` | 删除本地凭据（服务端吊销走 Web tokens 页） | — |
| `dmaf auth status [--market <base>]` | 调 `/api/me` 报告当前登录身份 | 0（未登录也 0）/ 3 |
| `dmaf publish [<dmaf目录>] [--project] [--version] [--bump] [--intro <文件>] [--github-url] [--market <base>] [--dry-run]` | 发布流水线（前四步零请求）：① 登录态 → ② 门禁一编译（零错误）→ ③ 门禁二 doctor 核心（**仅 error 级拒绝**：layout/artifacts_drift/manifest；`.dmaf` 卫生为 warning 放行）→ ④ 本地预检（manifest name、版本与 project 正则、介绍三要素 1–2000/1–2000/1–4000 纯文本、包完整性、E-9 按发布者账本**排除其他已安装包的文件**并列出、成员数/解压总量/压缩上限）→ ⑤ **确定性打包**（tar.gz：路径排序、mtime/uid/gid=0、mode 0644、gzip 头 mtime=0/OS=255/级别固定——market 以服务端字节 SHA-256 判幂等）→ ⑥ multipart 上传 `POST /api/publications`（meta JSON + package 字节流，Bearer PAT）→ ⑦ 响应处理（201 幂等重放安全重试；409 version_conflict 提示 `--bump`/`--version` 升版不重试；`content_integrity_violation` 禁止重试）。`--bump` 一键升版：递增 manifest version 数字尾段并回写；`--intro` 缺省交互补问；`--dry-run` 打包出摘要不上传。**publish-only**：无更新/覆盖/下架，更新 = 升版重发 | 2 未登录/地址/用法；3 门禁/预检/4xx；4 版本冲突；5 限流/5xx 重试穷尽/完整性异常 |

market 底座约定：地址解析顺序 `--market` > 环境变量 `DMAF_MARKET_URL` > 用户配置（`credentials.toml` 的 `[default] market`）> 内置默认实例（`https://dmaf.aicoffe.com`）；只接受 `https://`（`http://` 仅 localhost/127.0.0.1/[::1]）；凭据环境变量 `DMAF_MARKET_TOKEN` 可临时覆盖不落盘；输出/日志只显示 token 前 12 字符；每次命令生成一个 `X-Request-ID`；错误信封（code/message/details/trace_id）统一映射到引擎退出码 2/3/4/5；可重试错误（网络/503 blob_unavailable/500 sys_internal_error）同一份字节重试 ≤3 次指数退避。

`--harness` 接**名称**（install/check/doctor/compile 通用），由引擎解析为项目根下的目录与布局：
`opencode`→`.opencode`、`claude`（别名 `claude-code`）→`.claude`、`zcode`→`.zcode`、`cursor`→`.cursor`、`gemini`（别名 `gemini-cli`）→`.gemini`（flat-md，md 原样复制）；
`codex`→`.codex`、`dsh`→`.dsh`（toml-agents，agent 转换为 TOML，`mode` 以 `# dmaf-mode:` 注释保留）；
skills 一律整目录复制（源侧支持一层分类子目录 `skills/<分类>/<技能>/`；**opencode、cursor 支持嵌套发现**，安装保留分类路径，其余 harness 按技能名拍平；技能名须全局唯一）。形如路径的值（含分隔符或 `.` 开头）按 flat-md 透传；未知裸名报错（退出码 2）。
项目侧可选配套：`dmaf/harness/<名>/` 为该 harness 的**会话入口配置源**（install 时落位项目根），
`dmaf/manifest.yaml` 声明工作流包身份与 `engine` 版本范围（doctor 判定兼容；add/push 合并核心共用）。

### 运行期（零 harness 依赖：任何运行期命令不读 harness/注册表）

| 命令 | 说明 | 退出码 |
|---|---|---|
| `dmaf start --scope <name> --task "…"` | scope 模式：从 `dmaf/compiled/` 产物加载流程；需求原文注入保留变量 TASK（提取归流程内首个 stage）；机器调用可 `--var k=v`；`--locale zh|en` 指定会话人面文案语言（烘焙进会话，缺省 DMAF_LOCALE，再按系统语言 zh 系 → zh、其余 → en） | 0/3 |

| `dmaf next --session .dmaf/<dir>` | 计算下一跳指令（JSON）。带副作用时写 `action.dispatched` 分片；resume/重发无副作用 | — |
| `dmaf report --session <dir> --payload <file\|->` | 回报 action 结果或审批决定；Engine 校验产出物存在性后转移状态 | 3 schema 被拒；4 状态冲突 |
| `dmaf inspect --session <dir>` | 人读进度视图 | — |
| `dmaf log --session <dir> [--type T] [--stage S] [--limit N]` | 审计时间线（链异常时头部告警） | 2 |
| `dmaf verify-audit --session <dir>` | 哈希链校验 + 回放比对 | 4 |
| `dmaf cancel --session <dir>` | 取消工作流 | 4 |
| `dmaf replay --session <dir> [--overwrite]` | 按分片重建状态文件（默认写旁路文件） | 4 |
| `dmaf fork --session <dir> --seq N` | 从审计 checkpoint 分叉新会话 | 4 |
| `dmaf verify-determinism --session <dir>` | 确定性实证重放（重推全部路由决策与账本比对） | 1 不一致；3；4 |

## 指令载荷与 harness 解耦

`next` 指令的 action 携带 `skills: [名字名单]`（来自 stage 定义），**不再包含从注册表搬运的 `skill_brief`**——技能描述由 harness 执行期自供。skill 在 harness 中缺失属于执行期错误：agent 执行失败 → report failed → 用户修复 harness → 对同一 `--session` 重新 `next`（resume，未决 action 原样重发）。`compute_next` 因此是 `(产物/定义, 状态)` 的纯函数。

## 会话目录结构

`.dmaf/<YYYYMMDD-HHmmss>/` 是引擎运行独占区（gitignore 整目录），只含引擎簿记——**工作流产出物不在这里**，它们按 stage 定义 `inputs`/`outputs` 声明的完整路径写入项目根的业务目录（支持 `{SESSION_ID}` 分桶）：

```
.dmaf/<YYYYMMDD-HHmmss>/     # Engine 独占，LLM 与人都不要读写
├── dmaf-state.md            # 状态文件
├── last-report.json         # Orchestrator 写的单次回报草稿
└── audit/shard-*.json       # 追加式 SHA-256 哈希链审计分片
```

## 关键语义

- **状态机**：`pending → in-progress →（awaiting-approval ⇄ revising）→ completed / failed / cancelled`，全转移表在 `src/state.rs`。
- **产出物校验在 Engine**：report 时 Engine 检查期望输出文件是否存在，缺失即按 failed 处理；无输出工件的 stage（如 submit）以 subagent 确认为准。
- **重试**：`retry.max_attempts` 是初始尝试之后的重试上限（`1` = 最多重试 1 次共 2 次）；重试由 `retry.scheduled` 审计并在下一跳自动派发。
- **审批门**：`approval.required: true` 的 stage 成功后停在 `awaiting-approval`；`granted` → completed，`rejected` → revising（修订派发携带 `revision_feedback`），修订轮不限。
- **审批评审者**：`approval.reviewer: <agent>` 时，`await_approval` 指令携带 `payload.reviewer`（评审者 + 被审产出物路径），Orchestrator 先派评审者再以其结论发 approval report；`approval.granted/rejected` 分片记录 `reviewer` 以溯源。评审者缺失/不可派发由 `check`/`compile --harness` 在部署期校验。
- **委托报文预构造**：dispatch 指令的每个 action 自带 `delegation` 对象（路径字段与 stage 定义同名 `inputs`/`outputs`，值为模板解析后的完整路径、恒在；协议字段 + 流程变量按“会话 vars ∪ agent vars 声明集”平铺；规范 docs/schemas/delegation.schema.json），Orchestrator 原样转发给 subagent；action 顶层不含业务字段（knowledge_point 已移除，summary 顶层 course_id 同步移除，均由 vars 承载）。
- **交付文案模板**：scope/内联定义可声明 `completion_template`（`{vars.name}` /`{outputs.stage_id}`，占位符在定义/编译期校验），complete 指令渲染为 `payload.completion_text`；无模板则省略该字段，Orchestrator 退回转述 summary。
- **并行聚合**：以每个 agent 最后一次尝试为准；`on_exhausted: continue` 时带失败继续，下游输入不剔除缺失项。
- **确定性**：`instruction_id = ins-<workflow_id>-<审计序号>`，指令内容不含时间戳——同状态必得同指令（`tests/test_determinism.rs` 随机轨迹回归）。
- **fork**：非破坏性分支，哈希链延续；`SESSION_ID` 活绑定为新会话 ID，产物桶随之切换——分叉点前已完成的产物从源桶复制到新桶（结果 JSON 的 `copied_artifacts`/`missing_artifacts` 为新桶路径），两条分支互不覆盖；不含 `{SESSION_ID}` 的路径两侧同址、分支共享。分叉点不得有在途 action。重试失败阶段的推荐姿势：fork 回该 stage 派发前的 checkpoint 重跑。

## Hook（hooks.yaml）

项目级外部集成点：**引擎只按配置顺序调用，不读结果**。配置在定义层 `dmaf/hooks.yaml`（运行期读取，不入编译产物；缺失 = 无 hook，静默）：

```yaml
timeout_secs: 120          # 每个 hook 的等待上限（秒，全局，缺省 60；超时杀掉、列表继续）
init:                      # 可选：dmaf start 建会话前顺序执行，结果不影响启动
  - python dmaf/hooks/preflight.py
on-event:                  # 可选：键 = 审计事件类型（十种，见审计事件词表）
  action.reported:
    - python dmaf/hooks/upload.py
  workflow.completed:
    - [cmd, /c, npm, run, notify]   # Windows .cmd/.bat 包装器须显式过 cmd
```

- **两个点位**：`init`（start 建会话前，stdin 携带 workflow/scope/session_dir/vars/stages 快照）；`on-event`（**凡审计分片落盘**，按分片 event_type 查表，命中则顺序执行；stdin = `{"session_dir": ..., "shard": {…分片内容…}}`）。只读命令（next 重发/resume、inspect、log、verify-*、replay）不产生分片，永不触发。
- **命令写法**：统一 argv 语义——字符串按空白切分（不解析引号，路径含空格请用列表）、列表原样；直接 spawn 不经 shell；hook 继承引擎进程的 env 与 CWD。
- **结果零解释**：同步等 hook 退出（顺序执行，不并发），退出码与输出一律不读不判；单个 hook 失败不阻断列表，也不影响所在命令的 stdout JSON、退出码、状态与账本。hook stdout 转发到终端 stderr（引擎 stdout 契约是纯 JSON，不可被污染）。
- **禁耗时任务**：引擎同步等 hook，不要在 hook 内同步做耗时工作——上传/外部调用等落任务文件、由后台进程消费。
- **开关**：`--no-hooks`（start/next/report/cancel/fork 均可）或环境变量 `DMAF_NO_HOOKS=1`。
- **配置降级**：坏 YAML / 未知事件键 / 非法 timeout_secs → stderr 一行警告，有效部分照常生效；`dmaf doctor` 报告配置健康度。
- **责任边界**：hook 不参与路由——相同输入下带/不带 hook 的账本逐字节一致，hook 破坏确定性由用户负责（`verify-audit` / `replay` / `compile --check` 兜底）。运行期"拦截"需求的正解是审批门（`approval.gate`：停机 → 外部决策 → report 落审计），不是 hook。

## 恢复（resume）

状态全在磁盘上：会话中断后，新会话对同一 `--session` 直接执行 `next` 即可续跑（未决 action 原样重发，不产生新审计）。篡改检测用 `verify-audit`。

## 维护约定

- **定义层是唯一事实源**：`dmaf/workflows/`（工作流定义）、`dmaf/agents/`、`dmaf/skills/`（AI 资产，本仓库内容为样例）。改 AI 资产后用 `dmaf install --harness <name>` 安装到 harness（如 `opencode` → `.opencode`），不再手工 cp。
- **改工作流必须重编译**：改 `dmaf/workflows/stages|scopes` 后执行 `dmaf compile` 并提交 `dmaf/compiled/`；`dmaf compile --check` 守卫漂移。
- **harness 绑定校验**：部署期用 `dmaf check --harness <name>`（工作流引用 vs harness 实际内容）。
- 新增 stage：在 `dmaf/workflows/stages/<phase>/` 加 md 文件 → `dmaf compile` → scope 的 `include_stages` 认领；`task_description` 等业务文案全部在定义里，Orchestrator prompt 不含业务文案。
- Engine 修改必须保持 `cargo test` 全绿（179 例），特别是确定性测试。
- 指令/回报/审计分片的 JSON Schema 规范见 `docs/schemas/`；Rust 侧等价校验在 `src/schema_check.rs`，两边须同步修改。
