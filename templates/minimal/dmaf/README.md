# dmaf/ — Workflow definition layer

This directory is the **definition layer** of [dmaf](https://github.com/aicoffe/dmaf-engine) (the deterministic multi-agent engine): workflow and AI asset definitions, plus the `compiled/` build artifacts.

## Contents

- `workflows/stages/<phase>/<slug>.md` — stage definitions (frontmatter declaration + execution brief)
- `workflows/scopes/<name>.md` — scopes: `include_stages` membership + workflow-level metadata
- `agents/`, `skills/` — AI assets (agent frontmatter: name/mode/description; skills are `<name>/SKILL.md`)
- `hooks.yaml` — project-level hook configuration (fully commented by default = not enabled)
- `docs/流程定义指南.md` — flow definition guide: stage/scope fields, template variables, approval gates, compile error reference (written by `dmaf new`)
- `compiled/` — `dmaf compile` artifacts (byte-deterministic, committed, never hand-edited)

## Runtime layer and other areas (not in this directory)

- `.dmaf/` — **engine-exclusive runtime area** (session state and audit, gitignored). Neither agents nor humans read or write it.
- `.opencode/` etc. — harness derivatives (generated by `dmaf install`, gitignored).
- **Business deliverables** (workflow outputs) never go into `.dmaf/`: their full paths live in stage `inputs`/`outputs` (supports `{SESSION_ID}` session bucketing), inside your project's business directories — your version control decides whether to keep them.

## Writing workflow definitions

**Read [docs/流程定义指南.md](docs/流程定义指南.md) first.**

## The loop

```bash
dmaf compile && dmaf compile --check          # after definition changes
dmaf install --harness opencode              # deploy AI assets to the harness
dmaf check --harness opencode --stages dmaf/workflows/stages --scopes dmaf/workflows/scopes
dmaf start --scope <name> --var topic=X       # start a session (scope mode)
dmaf next --session .dmaf/<session-dir>           # next instruction (JSON)
```

Full command reference: the dmaf engine manual.
